# FVO-001-001 — Assigned identifiers were invisible to the book's author

## Identity

- **ID:** FVO-001-001
- **Title:** Assigned identifiers were invisible to the book's author

## Observer / source

Implementation-phase production verification, Edition Architecture
Phase 2 (Founder Office authorization), August 11, 2026 working
session.

## Validation cycle

Founder Validation Cycle 001

## Workflow stage

Publication preparation — artifact generation with identifier
consumption on the Publication Desk.

## Repository baseline

`49b015f` (Edition Phase 2 implementation commit); hosted ledger
40/40 at observation.

## Context

Disposable verification fixtures: a fixture book, an institutional
ISBN registration (imprint allocation, no external assignment, no
book link), an Edition + paperback assignment, and an
author-initiated print generation consuming the assigned identifier.

## Description

After institutional assignment shipped, the book's author could not
consume the ISBN the imprint had assigned to their own edition: the
registry's author read policy admitted only externally evidenced,
book-linked registrations, so under invoker RLS both the consumption
visibility guard and the eligibility function refused with
`isbn_not_eligible`. A first fix (migration 41) failed because the
policy's outer-row references were captured by the subquery's own
columns — one policy never matched, the other was overbroad.

## Classification

Implementation Defect

## Validation Theme

unassigned

## Evidence Strength

## Software capability affected

ISBN consumption eligibility (Metadata Consumption) and registry RLS
(Publication Metadata & ISBN), as extended by Edition Architecture
Phase 2.

## Publishing methodology affected

The author-first principle applied to identifiers: an identifier
assigned to a book belongs in that book's author's view — visibility
follows assignment, not only external evidence.

## Governing authority

Edition Architecture Phase 1 Blueprint §10, §26; Publication
Metadata & ISBN as-built (registry RLS); Metadata Consumption
as-built (eligibility); the RLS-first engineering constitution.

## Analysis

The eligibility extension was correct at the database boundary but
unreachable for authors because registry visibility had not been
extended alongside assignment. Additionally, unqualified outer-row
references inside RLS EXISTS subqueries are a recurring hazard
(column capture) — policies referencing the outer table must qualify
those columns explicitly.
