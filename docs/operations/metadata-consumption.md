# Publication Metadata Consumption — Phase 2 as-built record

Implements Publication Metadata Consumption Phase 2 under the approved
blueprint
([docs/blueprints/publication-metadata-consumption.md](../blueprints/publication-metadata-consumption.md)),
August 2026. Migration:
`supabase/migrations/20260816000000_metadata_consumption.sql`. Modules:
`lib/publication/{metadata-fingerprint,consumption,consumption-readiness}.ts`
plus the serializer successors inside
`lib/publication/{serializer,epub,print-serializer,print-paginate,print-validate}.ts`.
Surface: the Publication Desk's generation forms and artifact history.

## The Metadata Pin

Every artifact generated by a consuming serializer version carries an
**Artifact Metadata Provenance** companion
(`artifact_metadata_provenance`, one per artifact, immutable, no
delete grant — removal only through the artifact/book cascade):
the pinned finalized Bibliographic Record version (id + number), the
bmv-v1 canonical fingerprint, the selection basis (`active` by
default; `historical` requires a recorded reason), and the Identifier
Consumption snapshots. A deferred constraint refuses any consuming
artifact without its companion at commit
(`metadata_consumption_required`). Draft versions are structurally
unconsumable; `selection_basis = 'active'` is verified against the
record's live active pointer at insert.

## bmv-v1

The canonical metadata fingerprint, computed twice — TypeScript
(`metadata-fingerprint.ts`) and SQL
(`bibliographic_version_fingerprint`) — with the database refusing a
companion whose fingerprint disagrees with its own computation
(`metadata_fingerprint_mismatch`), exactly the pbc-v1 discipline.
Canon: netstring fields over UTF-8 in fixed order (derived facts,
authored fields, keywords, categories, contributors by position with
role and derived flag), list lengths included; uuids, timestamps, and
version numbers excluded.

## Serializer successors

- **hgp-epub 2.0.0** — adds to the OPF exactly what the candidate
  cannot know: `dc:publisher` (imprint constant), `dc:description`
  (publication description, when present), ordered non-derived
  `dc:contributor` entries with MARC relator role refinements (all
  ten governed roles map cleanly), and — only when deliberately
  consumed — the ISBN as an additional `urn:isbn` identifier. The
  package `unique-identifier` remains the institutional
  `urn:uuid:{candidateId}` in every case. No new visible content.
- **hgp-print 2.0.0 / hgp-layout 2.0.0** — the title page gains the
  imprint line; the structurally blank title verso becomes the
  deterministic copyright page: title (and subtitle), the recorded
  copyright line (else © year + author display, else absent),
  "Published by {imprint}" / "An imprint of {legal entity}"
  (Spanish wording under an es manuscript language), the consumed
  ISBN labeled as such, and publication notes — each line omitted
  entirely when its fact is absent, nothing fabricated (no legal
  formulas, no edition statements, no printing lines). **Body
  pagination and page count are unchanged** — the page occupies the
  verso 1.0.0 left intentionally blank. The governed CP1252
  repertoire applies to consumed metadata (fail closed);
  `hgp-print-production` validator 1.1.0 adds the copyright page to
  the folio/running-head-suppressed kinds.
- **1.0.0 behavior is byte-frozen**: generation without a consumed
  input reproduces the exact 1.0.0/1.0.0 bytes (golden-pinned in
  tests); nothing was backported.

## The widened reproducibility law

Pre-consumption serializer versions keep the original law: one
checksum per (candidate, format, serializer version). Consuming
versions (major ≥ 2, the institutional rule stated by
`serializer_consumes_metadata`) fix one checksum per (candidate,
format, serializer version, **pinned metadata version + consumed
ISBN**) — enforced at the companion insert, where every prior
consuming artifact already carries its pin. The same divergence
refusal (`reproducibility_mismatch`) applies at both the action and
the database.

## ISBN consumption

Per-artifact restatement of an externally evidenced fact, never
assignment: eligibility requires a current (`recorded`) registration
of this book with `externally_assigned = true` and at least one
evidence row — enforced in the resolver and again by the database
(`isbn_not_eligible`). The companion snapshots the normalized and
as-entered identifier, the disposition, and the verbatim external
format wording at consumption, so later corrections never re-read
history. Recorded-only registrations are intentionally non-consumable;
absence is valid and the default; the format-relationship judgment is
human (the eligible list shows the verbatim wording; nothing is
string-matched).

## Selection, coherence, and readiness

Generation selects the active finalized version by default; a
historical finalized version requires a reason; both ride the
existing generation authority — no new ceremony, no AI path. The §6
coherence gate refuses a releasable generation (EPUB, print
production) when the pinned version's derived identity disagrees with
the candidate's frozen title-page facts
(`metadata_identity_mismatch`); a print proof proceeds with the fact
reported. Consumption readiness (`consumption-readiness.ts`, pure,
tested) states the facts — active version, divergence, coherence,
identifier eligibility classes — and never acts.

## Security

The companion follows artifact visibility exactly: staff and the
book's author read; inserts only through the sanctioned recording
functions (`record_export_success_with_metadata`,
`record_print_export_success_with_metadata` — SECURITY INVOKER,
artifact + companion in one transaction); immutable by trigger; no
update or delete grants; no service_role anywhere.

## Intentional limitations

- The EPUB gains no visible copyright/colophon page in this phase —
  package metadata only (a future serializer evolution).
- Subtitle stays out of EPUB package metadata (the visible title page
  carries it; no implemented consumer needs the refinement).
- Keywords and categories are not consumed by either serializer —
  their consumer is future channel metadata.
- Regeneration of 1.0.0-era artifacts through the app ended with the
  2.0.0 cutover: historical artifacts, bytes, and provenance stand
  untouched and fully interpretable; the 1.0.0 generation paths
  remain in the repository, byte-frozen and golden-pinned.

## Future pressures (preserved, not begun)

Editions and institutional ISBN assignment (recorded-only identifiers
wait for them); Cover Production (title/byline from the pinned
version, the consumed print ISBN for the barcode, recorded page
counts); barcodes; ONIX/metadata export over pinned fingerprinted
versions; Release-side metadata recording (releases already inherit
consumption transitively through the artifact); channel/distribution
transmission; AI metadata drafting.
